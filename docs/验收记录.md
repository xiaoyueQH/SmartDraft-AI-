本页区分真实执行、确定性测试和教学模拟。当前节点结构、默认配置见其他实现文档；旧参数不再作为现行配置传播。历史详细输出保留于本机Git忽略的storage/verification，重新克隆仓库不保证具有这些附件。

## 当前验收结论

| 范围           | 已有证据                                                 | 结论边界                                   |
| -------------- | -------------------------------------------------------- | ------------------------------------------ |
| 顾问接待       | 浏览器自然沟通、记录来源、暂停生成及技术更新             | 不保证模型永远不会过度追问或错误归因       |
| 独立起草       | 真实LangGraph子图、原生工具、PG检查点、完整多章草案      | 完成不等于每段语义或SQL正确                |
| 事实与自动建议 | 用户要求附录、正文/汇总【自动生成】、技术更新覆盖旧建议  | 正文仍有漏标和超范围建议的样本             |
| 评审闭环       | 客户提交、负责人驳回、编辑重签、双方确认发布V1、刷新锁定 | 发布样本为人工修订稿，不能代替原稿质量验收 |
| 账号隔离       | 客户与管理员独立标签，后台权限及数据库归属回归           | 同一浏览器配置不是不互信账号的安全沙箱     |
| 恢复           | 浏览器刷新、主图HITL、同run子图检查点重入测试            | API重启后没有自动任务调度                  |
| Redis/并发     | TTL、版本/代次竞态、有界回源和故障降级回归               | 没有生产吞吐量或跨实例模型限流承诺         |

## 真实案例一：设备借用访谈与评审

2026-10-27，Chrome独立记录，20人团队和约50件设备；先选Go/Gin，后由客户指定Java 21、Spring Boot 3、PostgreSQL和Docker。

- “先记录、不生成”未产生草案，技术更新没有丢失原规则。
- 起草中刷新恢复原运行与对话，没有重复发送请求。
- 首轮全部四章完成后仍重复请求写章，最终误报部分完成；修复图终止条件后同案完整结束。
- 顾问生成稿仍有权限/状态冲突和无依据的验证声明；客户撤回与负责人驳回分别检查，原因和状态持久化。
- 页面内二次确认替代浏览器原生警报；取消无提交，确认才发送，项目/记录版本变化使旧确认失效。
- 人工修订草案后：客户确认，再由负责人编辑，双方确认被清空并退回草稿；重提后双方分别确认才发布V1，刷新仍锁定。
- 测试项目曾移入可恢复回收站；后续用户恢复查看并明确接受详细开发文档的方向。原有客户项目未被改写。

## 已知局部问题

以下是模型样本的具体问题，应保留全文局部修订：

1. 个别默认限制（如8小时预约上限）没有就近标【自动生成】。
2. 主管要求统计“人数”，局部写成“次数”。
3. 明确排除邮件，运维段仍带回邮件告警。
4. SQL的时间范围类型、有效状态过滤、GiST扩展及配置示例需工程校对，不能凭生成完成就执行。
5. 自动草稿的生成来源可在聊天执行记录追溯，历史样本不一定在单条业务处理历史中具有独立“创建”审计。
6. 失败或截断调用未必拿到完整供应商usage，运行累计量不能用于云账单对账。

程序可验证来源片段存在、Schema、权限、版本与事务边界；不能以这些检查替代完整语义评审。当前没有自动全篇审计模型，不能声称这些问题已全部消失。
