# SupportFlow 文档导航

产品目标是把客户的业务沟通转成工程师可评审、拆任务并据此开发的详细需求文档，随后管理需求变更、任务、交付与售后。本导航分别列出当前实现、后续开发和真实验收，避免把设计图当成已实现能力。

**待后续处理：文档内容质量与审查耗时尚未通过验收。** 已单列[待处理验收清单](验收记录.md#待处理验收清单)，包含Q01～Q04、验收条件、原始证据与测试项目恢复入口；处理其他工作后从该清单继续。

## 后续开发入口

[后续开发说明：四个业务智能体与分块需求文档](后续开发说明.md)是唯一后续方案。架构方向已确认：**四个业务Agent＋统一主控调度层＋统一交接协议**。核心改造包括稳定分块、公共设计约定、依赖分批生成、局部更新和最近一次差异撤销；不是让四个Agent重新生成整篇文档。

按P0～P6逐阶段开发：交接契约→只读块目录→增量与撤销→首次分批生成→独立审查质量→实测验收→正式变更复用。2026-10-31已实现P0交接、P1稳定目录、P2局部更新与撤销；需求生成现为5节点。设计依赖与首次分批生成属于P3，当前验收证据见验收记录。

## 图与示例的含义

- **业务流程图**帮助理解客户和系统的交互，包含人工步骤。
- **节点图**对应代码中的 `add_node/add_edge/add_conditional_edges`；图中明确注明工具内部动作，避免误认为每个动作都是节点。
- **模拟执行**是说明一条合法轨迹的教学示例，模型可以选择其他工具次序，不能把它当作已经发生的真实运行。
- **验收记录**单独列出真实证据、使用条件和未通过项。生成完成、内容正确、双方确认发布是三件分别检查的事。

## 当前边界

系统已接入真实模型和真实数据库；文档中的模拟案例只用于解释机制，不是产品里的“演示流程”。当前没有向量 RAG、附件解析、外部项目平台集成、代码执行、自动开发、自动报价或自动排期。Skill/MCP 不是现有运行链路，不应画成已实现节点。

文档中的默认参数以 [配置代码](../backend/config.py) 为准；[.env.example](../.env.example) 说明一套示例部署，不能把示例模型名当成所有环境的实际配置。
