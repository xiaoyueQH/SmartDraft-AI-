# 商品与订单查询

当前完成商品目录、单商品下单、订单列表、购买明细快照、物流、[两阶段确认取消](cancellation.md)与[演示履约和整单退货退款](fulfilment.md)。真实支付/退款/物流、换货及 Agent 尚未接入。演示数据来自初始化脚本，自行构造，不调用真实商家、支付机构或物流服务。

## 数据与初始化

```powershell
conda activate D:\code\env\supportflow
python scripts/migrate.py
python scripts/seed_demo_users.py
python scripts/seed_demo_orders.py
```

迁移 `0003_orders` 创建 `products`、`orders`、`order_items`、`shipments`、`shipment_events`。商品库存为模拟数值；金额使用整数分。订单明细保存购买时名称、SKU 和单价，后续商品改名或调价不会修改历史明细。

初始化只为启用的普通账号 `user` 创建 3 个商品、5 笔订单，初始覆盖待付款、待发货、运输中、已签收、已取消。运输中与已签收订单带模拟物流事件。造单事务持有账号行锁并使用确定性 ID；随后在独立事务中为可取消演示订单补齐预占并扣减库存，重复执行不会重复造单、重复预占或覆盖已有进度。脚本不创建登录账号、不重置密码、不在 API 启动时执行。

新账号没有订单时返回空列表；不会把 user 的演示订单分配给其他账号。

## 接口与权限

| 接口 | 权限与含义 |
|---|---|
| `GET /api/products` | 登录后读取商品目录 |
| `GET /api/orders` | 仅当前账号的订单 |
| `GET /api/orders/{id}` | 当前账号的明细和物流 |
| `GET /api/admin/orders` | 管理员跨账号查询 |
| `GET /api/admin/orders/{id}` | 管理员查看订单详情 |

HTTP 路由校验管理员角色，业务服务再次校验跨用户权限。普通用户传入其他账号 ID 或 `all_users` 参数不能扩大查询范围。越权订单和不存在订单都返回 `404 / ORDER_NOT_FOUND`；普通用户访问管理接口返回 403。身份和角色仍以数据库有效会话为准。

订单列表支持 `status`、完整订单号 `number`、`limit`、`offset`。默认每页 20、最多 100、offset 最多 10000；按创建时间与 ID 稳定倒序排序。返回 `{items, has_more}`，通过多取一行判断下一页，避免每次请求扫描全表计数。规模扩大后再根据真实查询量换游标分页。商品按唯一 SKU 排序分页。

每个请求独立异步会话，查询在短事务内完成。详情在 PostgreSQL 使用 REPEATABLE READ READ ONLY，确保多次查询的状态、物流与取消审计来自同一快照。物流事件按运单批量查询，没有逐运单的 N+1。未持有数据库连接调用任何外部工具。请求受现有并发准入、连接池与 SQL 超时预算保护。

## 页面与边界

用户端 `#/products`、`#/orders`；后台 `#/admin/orders`。用户端没有后台入口。列表支持查询、分页、刷新和空状态，详情展示金额明细与物流时间线。分页使用已提交的筛选条件，新查询回到第一页；切换订单详情会取消旧请求并丢弃过期响应，离开页面也会取消请求。

页面保留演示环境说明，查询失败展示可重试提示。付款、发货、收货和售后入口位于订单详情，按身份和当前状态展示；取消先预览后确认，所有写入都要求核对确认。详情的付款、退款、工单、取消与订单事实在同一数据库快照读取；一对一关联合并查询，物流事件批量读取。
